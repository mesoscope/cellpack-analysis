# cellpack-analysis

Analysis pipeline for the paper

> Mogre SS, Li R, Scibisz A, Do TP, Dixon JC, Viana MP, Nazockdast E, Rafelski SM, Theriot JA,
> Riel-Mehan MM, Johnson GT. *Geometry-aware modeling with cellPACK for evaluating spatial trends
> in intracellular organization.* Protein Science (2026).

The code compares observed organelle positions (peroxisomes, endosomes) in the
[WTC-11 hiPSC single-cell image dataset](https://open.quiltdata.com/b/allencell/packages/aics/hipsc_single_cell_image_dataset)
with models generated by [cellPACK](https://github.com/mesoscope/cellpack) under simple modeling
rules, using distance distributions, Monte Carlo envelope tests, and available-volume-normalized
occupancy ratios. It regenerates every computed figure and table of the paper from released input
data.

## Installation

Requires Python 3.11 and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/mesoscope/cellpack-analysis.git
cd cellpack-analysis
uv sync --frozen
```

The cellPACK engine is installed from the git revision pinned in `pyproject.toml`
(`[tool.uv.sources]`, cellPACK commit `5c31f56d89697f977f54ee001209eff92047b35c`) and runs as a
subprocess from the virtual environment's copy. Do not set `CELLPACK` or `PYTHONPATH`.

`data/` (inputs) and `results/` (outputs) live at the repository root and are git-ignored, except the tracked `data/templates/`.

## Reproducing the paper

Everything is driven by one script, one stage per call:

```bash
bash cellpack_analysis/analysis/workflows/run_paper.sh <stage>
```

Run with no argument for the stage list. `STRUCTS="peroxisome"` (or `"endosome"`) restricts the
per-structure stages to one structure.

### 1. Fetch the input data

```bash
bash cellpack_analysis/analysis/workflows/run_paper.sh fetch
```

This downloads 26 sha256-pinned archives (4.99 GB) over anonymous HTTPS from
`https://cellpack-analysis-data.s3.us-west-2.amazonaws.com/release/v1.0.0/` and extracts them into
`data/` (30.68 GB, 43,876 files): the cell cohort and puncta tables, meshes, per-cell available-space
grids, observed positions, and the published packings (positions of 99 replicates per cell for each
modeling rule, the mixed rule, the decay-length ladder, and the sources-of-variation packings). See
[`cellpack_analysis/data_release/README.md`](cellpack_analysis/data_release/README.md).

### 2. Run the analysis stages

`analysis` runs `calibration` through `manuscript` in the order below. Each stage can also be run
alone. Outputs go to `results/`. Runtimes are wall times per structure (peroxisome / endosome),
measured from empty caches on one SLURM node with the CPUs and memory shown; with the two
structures in parallel the whole chain took 8.6 h (about 210 core-hours).

| Stage | Produces | Config (under `cellpack_analysis/analysis/workflows/configs/` unless a full path is given) | Runtime |
|---|---|---|---|
| `fetch` | input data in `data/` | `cellpack_analysis/data_release/configs/paper_inputs.json` | download-bound (4.99 GB) |
| `calibration` | envelope calibration (Methods rates); writes the distance cache `distance` reuses, so it runs first | `distance_analysis/distance_analysis_{peroxisome,endosome}_replicate_99_v4_calibration.json` | 27 / 28 min (16 CPUs, 96 GB) |
| `distance` | distance distributions, EMD, KS, per-cell envelope tests | `distance_analysis/distance_analysis_{peroxisome,endosome}_replicate_99_v4.json` | 42 min / 1.4 h (16 CPUs, 96 GB) |
| `distance-supp` | nearest-neighbor and pairwise distances | `distance_analysis/distance_analysis_supp_{peroxisome,endosome}_replicate_99_v4.json` | 7.6 / 8.1 h (16 CPUs, 128 GB) |
| `occupancy` | per-rule occupancy curves, occupancy EMD | `occupancy_analysis/occupancy_analysis_{peroxisome,endosome}_replicate_99_v4.json` | 13 / 17 min (16 CPUs, 96 GB) |
| `fit` | NNLS rule-mixing fit with cross-validation; writes the mixed-rule packing and validation configs | `rule_interpolation_replicate_99_v4/rule_interpolation_replicate_99_v4_{peroxisome,endosome}.json` (`--phase fit`) | 37 / 33 min (16 CPUs, 96 GB) |
| `validate` | mixed-rule validation (distance, occupancy, AIC/BIC, per-cell envelope test) | same config (`--phase validate`) | 2.1 / 3.0 h (16 CPUs, 96 GB) |
| `ladder` | decay-length sensitivity | `rule_interpolation/rule_interpolation_tune_gradients_v2_{peroxisome,endosome}.json` (`--phase fit`) | 30 / 44 min (16 CPUs, 128 GB) |
| `biovar` | sources-of-variation analysis | `biological_variation/biological_variation_config.json` | 16 min (8 CPUs, 48 GB) |
| `illustrations` | descriptive tables and illustration panels (five notebooks in `cellpack_analysis/analysis/notebooks/`) | none (frozen constants in each notebook) | 26 min (4 CPUs, 48 GB) |
| `manuscript` | drop-in figure panels, numbers sheets, calibration summary in `results/manuscript_figure_assets_v4/` | `manuscript/manuscript_replicate_99_v4.json` | 2 min (8 CPUs, 96 GB) |

`validate` needs the `fit` outputs. `fit` rewrites the tracked `mixed_rule_validation_config_{peroxisome,endosome}.json` in `configs/rule_interpolation_validation/replicate_99_v4/`, so `git diff` after `analysis` shows any change. `manuscript` redraws every panel from the caches the earlier
stages write (set `SOURCE_DATE_EPOCH` for byte-reproducible PDFs) and writes `MANIFEST.md`; the
per-stage PDFs are the pipeline's own plots. The `illustrations` stage needs ~24 GB RAM
(Fig 4b pools ~1e8 KDE points). The KS bootstrap is seeded (`ks_bootstrap_seed: 0` in the v4
configs).

The stages write derived files into `data/` (merged `all_positions_*.json` next to the packings),
so `data/` must be writable. Figures match the published PDFs pixel for pixel only with the Arial
font installed; otherwise matplotlib falls back to DejaVu Sans, which changes only the text.

### Optional: repack the models

The analysis uses the published packings, so repacking is not required. The packing stages submit
SLURM jobs (default partition `aics`; see `cellpack_analysis/packing/README.md` for the options) and
are asynchronous:

| Stage | Action |
|---|---|
| `pack` | stage-1 packings: 4 rules x 2 structures x 99 seeds |
| `stage2-config` | copy the fit's mixed-rule packing config into `cellpack_analysis/packing/configs/replicate_99_v4/` (after `fit`) |
| `pack2` | mixed-rule packings (after `stage2-config`) |

Packing writes into `data/packing_outputs/`, the paths `fetch` fills with the published positions, so
repack in a separate clone. `stage2-config` overwrites the tracked
`<structure>_replicate_99_v4_interpolated.json`; `git diff` shows whether the refit coefficients
differ from the tracked ones. The decay-length ladder and sources-of-variation packings have their
own configs in `cellpack_analysis/packing/configs/` and are not part of `run_paper.sh`.

Fig 2, Fig S3 and Table S1 (sources of variation) use packings made in Feb 2026 with an older engine
(`14225bcb` for shape, baseline and variable_size; `ae4f0aa6` or later for variable_count). Their
positions ship as inputs of record. Two `shape` cells repacked at the release pin reproduced them
byte for byte; the other variants were not checked.

At the release pin, repacking reproduces the published `positions_*.json` byte for byte (checked
on 3 cells x 4 rules x 99 seeds, 2 mixed-rule cells x 99 seeds and 4 decay-length packings), with
one exception. The engine builds each cell's grid on first use and caches it in
`data/structure_data/<id>/grids/` (not shipped), and the first seed packed right after a build
differs from the published one. Once the grids are cached, repack with `skip_completed: false` to
reproduce all 99 seeds. A 99-seed recipe takes 16-66 min on one CPU, plus 7-12 min for a grid
build. Importing cellPACK writes `./.creds` (a user name, not a credential) into the working
directory and refreshes a path-preferences file inside the virtual environment from the network.

### Regenerating recipes without packing

Recipes embed absolute data paths, so the shipped recipes are provenance. To regenerate recipes and
packing configs without running cellPACK, fetch the cell tables and meshes, then use `--dry-run`:

```bash
uv run python -m cellpack_analysis.data_release.paper_inputs fetch \
    --groups tables,meshes_SLC25A17,meshes_RAB5A,meshes_mean
uv run python -m cellpack_analysis.packing.run_packing_workflow \
    -c cellpack_analysis/packing/configs/replicate_99_v4/peroxisome_replicate_99_v4.json --dry-run
```

The output lands in `data/recipes/` and `data/configs/`. Regenerated recipes are byte-identical to
the recipes of record except for the absolute data directory prefix they embed (18,541 recipes
checked).

### Preprocessing

Preprocessing from the Quilt dataset (`aics/hipsc_single_cell_image_dataset`) is documented but not
part of the reproducibility check: its outputs ship as inputs. The scripts are in
`cellpack_analysis/preprocessing/`; meshes are decimated with `vtkDecimatePro` (target reduction
0.95).

| Script | Output |
|---|---|
| `get_structure_images.py` | segmented images (`data/structure_data/<id>/{sample_8d,full}/segmented/`) |
| `get_meshes_from_images.py` | nucleus and membrane meshes (`data/structure_data/<id>/meshes/`) |
| `get_structure_coordinates.py` | observed puncta positions (`positions_<id>.json`) |
| `calculate_available_space.py`, `submit_available_space_slurm.sh` | per-cell available-space grid distances (`grid_distances/`) |
| `get_structure_size_and_count.py` | `data/structure_stats.parquet` (puncta count and size) |

## Repository layout

| Path | Contents |
|---|---|
| `cellpack_analysis/analysis/` | analysis workflows (`workflows/`: `run_paper.sh`, analysis, rule-interpolation and manuscript runners, JSON configs) and illustration notebooks (`notebooks/`) |
| `cellpack_analysis/data_release/` | released-input tooling (`paper_inputs.py`) and the BioFile Finder / Simularium data-release workflow |
| `cellpack_analysis/lib/` | shared library: distances, occupancy, statistics, rule interpolation, plotting, I/O |
| `cellpack_analysis/packing/` | recipe and config generation, rule definitions, local and SLURM packing launchers, packing configs |
| `cellpack_analysis/preprocessing/` | images, meshes, coordinates and available space from the Quilt dataset |
| `tests/` | pytest suite |

## Tests

```bash
uv run pytest tests
```

Always pass `tests`; never run bare `pytest` from a checkout that holds `data/`. The full suite is
long, so running single files is practical (`uv run pytest tests/test_paper_inputs.py`). `make build`
runs the same command.
